# 评测设计

## 图价值消融
A: Pi + 源码/文本工具。B: A + 按需图工具。C: B + 简单规则建议。D: B + Jev 建议。
使用固定主模型/参数、快照、工具输出预算、验证协议和同一黄金集。
记录有效召回、clean PR 误报、证据有效性、重复、完整交付、总 token/cost/时延。
区分 cold/warm 构图，路由开销计入总成本。不得把缺失报告当作零误报。

## Finding 协议
A: 原生会话 + final_only。B: 原生会话 + incremental_candidates。
同一完成标准；故障点包括首次完整输出之前、成熟候选之后、压缩、最后输出和报告写入。
记录中断后保留的有效结果、额外工具数、误报/撤回率和最终交付率。
增量工具无法保存模型还没有产生的有效调用，不能宣传为全程“发现不丢失”。

## 图正确性
静态 fixture：同名跨作用域、别名/相对导入、继承、动态注册未解析、语法错误、删除/重命名、
Unicode 行列、base/head 对齐、增量等价全量。结构化 edge 也需 provenance。

## 恢复与服务边界
同一快照/分支的重复工具请求、截断 JSONL、错误日志行、写失败、进程中断、
用户取消、旧建议迟到、并行工具竞争、PR 更新和重复发布。

## Shadow
一致率不是正确率；先人工标注/对照局部路径，再做端到端随机或配对实验。
采用隔离有界队列，不让 shadow 改变 prompts/tools/args/results；测量实际资源开销。
