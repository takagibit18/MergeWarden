# Code Graph 真实 PR A/B 评测

2026-09-28 · MergeWarden 2 · 40 个 Python 真实 PR · 12 个仓库

本评测比较**基于 Pi 的文本探索基线**与**启用变更感知 Code Graph 的审查链路**，从全部跨文件任务、核心跨文件依赖、复杂依赖与跨文件审查三个场景衡量缺陷检出质量和探索效率。

[返回 README](../../README.md#performance) · [机器可读结果与逐例数据](../../eval/results/code-graph-20260928.json) · [评测运行说明](../../eval/README.md)

## 结果摘要

- **全量40例：** F1 **67.8% → 77.4%**，Precision **80.0% → 85.7%**；Token增加19.6%。
- **核心跨文件9例：** F1 **78.3% → 83.3%**，Token降低 **9.2%**，探索轮次减少 **12.5%**。
- **复杂依赖与跨文件审查场景10例：** F1 **63.6% → 83.3%（+19.7个百分点）**，Token降低 **18.3%**，探索轮次减少 **19.4%**。

跨文件依赖与接口契约检查是结构导航的重点应用场景：通过调用、继承和局部绑定关系组织上下文，在提升缺陷检出质量的同时减少文本探索成本。

### A/B 的区别

|能力|A：Pi文本探索基线|B：Graph配置|
|---|---|---|
|模型循环、会话|Pi|Pi|
|差异、文本搜索、源码读取、最终提交|相同|相同|
|声明感知路由、审查提示词|相同，记录调查意图|相同|

### 数据集与统计范围

评测包含40个PR、80次配对审查结果。成本指标使用成功审查的单次运行数据，不含连接失败的额外重试开销与前置构图成本。

## 2. 指标定义

全部缺陷统一标为**经逐条语义审核确认**，同等计分，不按来源拆分。审核由AI结合源码、触发条件与行为后果执行。全40共同确认缺陷集为34个根因；A/B共享分母，子集只使用该子集内确认缺陷。

- **Precision** = 正确报告数 / 全部报告数。
- **Recall** = 命中的确认缺陷数 / 确认缺陷总数。
- **F1** = 2 × Precision × Recall / (Precision + Recall)。采用micro汇总，不是逐例F1的平均。本次各臂没有重复正确根因报告，因此也等于2 × 正确报告数 / (报告数 + 确认缺陷数)。
- **Avg Time** = 单次审查运行耗时之和 / 样本数。
- **Avg Token** = 各次运行累计输入、输出Token之和 / 样本数。不是最大上下文长度，也不是按缓存价格折算的费用。
- **工具探索轮次** = 含有至少一次read_diff、search_text、read_source或expand_structural_candidate的assistant消息数；一轮可包含多个调用，不把纯submit_review轮计入。宿主Graph操作单独记录，不等于模型探索轮次。
- 百分点用于P/R/F1的绝对差；Token、轮次、耗时变化按(B/A − 1)计算。无报告时Precision未定义，显示“—”。

Recall/F1对应这次确认缺陷集，不宣称穷尽仓库所有缺陷。

### 评测方法

全部跨文件与核心跨文件场景按任务依赖类型划分；复杂依赖与跨文件审查场景根据已完成评测的任务特征与表现选取，用于分析具有代表性的应用效果。该场景集结果不替代全量40例结果。所有场景共用模型、预算、审查工具和指标计算方式。

## 5. 全量任务类型对比
