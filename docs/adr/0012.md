# ADR-0012 · MVP 快照、持久化与交付门槛

状态：用户已确认；v0.1 离线实现，真实模型验收待用户配置。

## 决策

引擎冻结输入并生成身份；客户端不得构造可信快照。提交版本使用真实 commit ID；index/worktree 版本用内容 ID，不伪造 Git 提交。仓库标识、两端内容、提交身份、输入种类和模型配置指纹决定快照身份。相同快照可复用，不覆盖旧清单。

内容存于仓库之外，经路径及 hash 核验读取；提交/index 使用 Git 对象批读，不执行 diff 驱动或文件过滤器。工作区读取包含 realpath、符号链接检查、读前/后状态及二次捕获验证。HEAD/index 在捕获前后核对；发现竞争修改拒绝并重试。未跟踪文件须显式选择且不在忽略范围。权限/资源失败不作为空结果。

MVP 使用一个 Pi 会话和 final_only。read_source/read_diff/search_text/submit_review 为唯一工具；未实现图工具时不注册占位查询。候选需有结构、版本、准确行范围/hash 和已读差异覆盖；接收为人工复核建议，不把完整性当作缺陷语义证明。

## Pi 持久化

M0 已确认 SessionManager.create 延迟首条 assistant 前的落盘。生产路径先用 `wx` 独占创建空文件，再使用公开 SessionManager.open 初始化。Pi 原生 header 与 CustomEntry 能在首条回复前写入，不需要虚构 assistant 或修改 SDK。

每次业务事件前后及原生消息结束后同步文件并核对磁盘与 SessionManager 条目。失败后 journal 永久失败并取消本次会话；不在可能分叉的内存状态上继续交付。只维护 Pi 原生消息日志，业务事件不额外进入模型上下文。真实 SDK 的故障注入验证原生消息写失败会阻止下一工具执行。

## 报告和中断

JSON、Markdown 分别临时文件写入、fsync、原子替换；交付清单最后写入且包含两份 hash。客户端完成结果在全部写入后返回。Windows 没有可移植的目录 fsync，因此不宣称所有文件系统/断电场景的数据库级事务；缺失清单或 hash 不匹配永不算交付成功。

硬中断可能保留 running 状态及锁；它不是当前进程活跃的保证。诊断检查锁拥有者；仅已退出进程的锁可由显式命令清理。新 run 可复用原快照，关联旧 run，但不续接中断会话。报告失败也不回滚或删除此前已保存的产物。
